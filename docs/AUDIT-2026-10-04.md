## 3. ML reality check

**Is there any real ML today? No.** The repo contains no model, no data, no training code and no ML dependencies.

**Ready to start the ML work? Not quite.** Before the first notebook you need:
- An `ml/` folder with `configs/`, `src/`, `notebooks/` and `reports/`.
- A separate `ml/requirements.txt` (torch, torchaudio, transformers, datasets, scikit-learn), kept apart from `backend/requirements.txt`.
- New `.gitignore` entries. The current one doesn't cover `ml/data/`, `*.wav`, `*.pt`, `*.safetensors`, `wandb/` or `.ipynb_checkpoints/`. **This is the biggest risk of committing gigabytes by accident.**
- Confirmed access to PodcastFillers, plus a download script.
- An evaluation script for event-level F1, written *before* any model, so the baselines have something to be measured with.

Also note that the roadmap puts **auth first (step 1)**. ML starts at step 2.

## 4. Software engineering and security

No secrets are committed. Both `.env.example` files contain only placeholders. `.env` and `.env.*` are ignored, and `!.env.example` keeps the examples tracked.

**MUST FIX (before or during the auth milestone)**
- **No CORS middleware** in `backend/main.py`. The first `fetch` from `localhost:5173` to `:8000` will be blocked. Use an explicit origin list, never `*` together with credentials.
- **No code reads the env vars.** The backend has no settings or `.env` loading (no dotenv or pydantic-settings), and the frontend never reads `import.meta.env`. The READMEs tell you to "fill in your Supabase values", but nothing uses them yet.
- **Add the ML ignore patterns** listed in section 3 before any data lands in the repo.

**SHOULD IMPROVE**
- **Practice cards are `<div onClick>`** (`App.jsx:146-180`), so keyboard users can't reach them. Make them `<button>`s. This fits naturally with the planned modes list that has a `status` field.
- **Progress is hard-coded in two places:**
  - Home: `72%` in the JSX (`App.jsx:191`) and again as `width: 72%` in CSS (`index.css:226`). The two can drift apart.
  - Session: `20%` inline (`App.jsx:72,78`).
- **Avatar initials "SK" are hard-coded** (`App.jsx:22,97`). On the session screen the avatar button navigates home, which is unexpected. On the home screen it does nothing.
- **"Start Speaking" has no handler** (`App.jsx:59`). That's fine for a mockup, but it looks like it should work.
- **The navbar is duplicated** across both screens.
- **Copy still says the old modes:** "storytelling, confidence, and humor" (`App.jsx:125`). Humor is still clickable and there's no Interview card. Both contradict `CLAUDE.md`'s scope.
- **`requirements.txt` pins only the 2 direct dependencies.** Transitive ones like starlette and pydantic float. Pinning the full set (e.g. a lock file) makes installs reproducible.
- **No Python version is recorded.** Your venv runs **3.14.6**, and Kaggle/Colab will run something older. Add a `.python-version` file or a note in the README.

**LATER**
- Split `App.jsx` into components once routing arrives.
- `package.json` uses caret ranges, which is fine because `package-lock.json` is committed.
- `frontend/.gitignore` repeats rules from the root `.gitignore`. Harmless.

**Dead code:** none. The Vite template leftovers were already removed in `af6108a`.

## 7. Future confusion risks

1. **MIT license vs non-commercial data.**
   - *Why it's confusing:* weights trained on PodcastFillers can't be MIT-licensed.
   - *Where:* `LICENSE`, and later the HF Hub model card.
   - *What to do:* state on the model card and in the README that the code is MIT but the weights are non-commercial.
2. **The docs describe the future in the present tense.**
   - *Why it's confusing:* you could over-claim in an interview.
   - *Where:* `CLAUDE.md` layout and roadmap, the README.
   - *What to do:* add a "Built / Not built" section to the README.
3. **Score fields with no source.**
   - *Why it's confusing:* nothing says whether confidence, fluency, grammar and vocabulary come from the model or from LLM opinion. You'll be asked how they're computed.
   - *Where:* `scores` table in `CLAUDE.md`.
   - *What to do:* decide which scores are measured and which are LLM-generated, and record it in DECISIONS.
4. **Two Python environments.**
   - *Why it's confusing:* backend 3.14 locally vs ML on Colab/Kaggle means version mismatches at serving time.
   - *Where:* `backend/venv` and the future `ml/`.
   - *What to do:* pin versions per folder, and test loading the model in the backend environment early.
5. **Mode names are bare strings.**
   - *Why it's confusing:* `"Humor"`, `"Conversation"` and the others are repeated by hand, and they'll have to match the `sessions.mode` values in the DB.
   - *Where:* `App.jsx`.
   - *What to do:* create the planned modes list with ids and a status field.
6. **`.env` files exist but do nothing.**
   - *Why it's confusing:* you may think the config is wired up when it isn't.
   - *Where:* both `.env.example` files.
   - *What to do:* wire them up in the auth milestone.
